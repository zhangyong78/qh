## 剩余4项最小修复

### 1. 参数入口和策略选择不可靠

`BuildParametersOrDefaults` 无条件给所有策略注入 fast_period、slow_period、average，无参数的 `preheat_signal.py` 等可信合法策略会被 ValidateParameters 以未知参数拒绝。加载时又把全部默认值写进参数JSON，随后JSON覆盖独立快慢周期控件，修改这些控件会被默认JSON静默覆盖。选择新文件/手动改路径未使 `_strategyDescriptor` 失效；Replay 只在 null 时加载，可能显示策略B路径却执行已缓存策略A。

最简单方案是保留一个通用参数JSON来源、移除重复示例专用编辑项；或保证仅绑定当前策略已声明参数且各编辑项同步，不能存在静默优先级。路径/文件版本变化应标未校验，回放前必须校验对应版本。文件名非法/空路径处理移入 try，避免 async void 异常退出窗口。验证无参数策略、独立 period 参数策略、示例参数改动和切换A→B确实使用B。

### 2. 历史结果图表没有绑定其数据快照

`OpenRunButton_Click` 读信号但没有加载 record.SnapshotId，继续使用当前 `_bars`。标记和定位只比 BarStart；不同合约同时间会叠到错误图表，不匹配时 FirstOrDefault 又把索引当0仍声称定位成功。新导入/加载快照也没有处理旧结果标记。当前也没有已有快照选择入口，用户只能新导入或打开最新数据。

补已有本地快照选择，按合约/周期/范围标识（复用现有SQLite清单，不新建管理框架）。只读打开run后加载其绑定快照，质量/图表/结果保持同一上下文；新数据选择时清除或明确切换旧信号上下文。定位/叠加核对快照和合约/周期/起止边界，无匹配给明确原因。打开已有run不得覆盖新研究的区间表单而混入错误策略/参数，至少清楚区分结果查看和新研究配置。验证两个不同合约具有相同时间的快照及重开旧run，不执行Python、不改写结果。

### 3. 新增策略加载未加入窗口退出和并发管理

关闭路径只追踪导入、查询、回放和G1Worker，没取消/等待 `_strategyLoadCancellation` 对应任务；模块加载中关闭窗口可遗留Describe进程至超时。加载按钮也未防并发，第二次加载可能 Dispose 前一次令牌并使旧描述覆盖新描述。

追踪策略加载Task及本轮令牌，关窗确认、取消及等待必须覆盖它；重复点击要禁用或取消并确认旧任务结束，避免旧结果覆盖新选项。这是现有加载链路收尾，无需后台服务。补加载中退出路径的应用自检/诊断及并发选择回归，实际人工点击仍诚实待验。

### 4. 错误位置与实时stderr尾部仍不足

运行错误只收到 `str(exc)`，没有策略Python文件/行号/栈；bar_start/bar_end不是代码错误位置。根独立错误和协议超时输出都显示 `stderr=<stderr unavailable>`。`ReadStderrTail` 在写入流尚打开时调用 File.ReadAllText，文件共享模式会妨碍读取。

保留当前并发排空逻辑，修正日志共享读取；Python异常保存 traceback/明确代码位置到日志或协议，父进程错误详情可读取；先收尾再读取最终尾部，避免永久只显示不可用。验证故意指定行抛错，以及stderr夹具写入指定标记后抛错，错误详情应含文件/行和标记。不需要加完整调试器。
