# G5-A 本机提醒基础：设计与验收计划

日期：2026-10-04  
范围：在现有 G4 完成 K 线事件和本地 WPF 工作台上增加可独立验证的本机提醒账本、去重和最小实例控制。不进入正式 G5，不宣称真实 TqSdk 持续权限、断线现场或实时覆盖已通过。

## 边界

- 只消费 `LiveSessionCoordinator` 接受的完成 K 线；不使用墙上时钟自行触发策略。
- 软件内信号账本始终保留；桌面通知和声音是独立的可选尝试。
- 不接 CTP、不创建真实下单、不增加远程通知渠道、不读取或记录用户密码之外的任何新凭据。
- 预热、启动补缺、断线恢复的历史信号只记账，不弹窗、不播声音。

## 持久化设计

G5-A 使用 SQLite 增加三类记录：

1. `live_instances`：实例配置、状态、通知/声音开关、暂停截止时间和最近完成 K 线。
2. `live_signals`：按实例、策略版本、合约、周期、K 线结束时间、类别、方向建立唯一业务键；记录来源阶段和是否允许提醒。
3. `live_notification_attempts`：每个业务信号的通知/声音尝试状态，区分待尝试、已尝试、失败、暂停/静音/冷却抑制和恢复期历史信号。先写信号与尝试状态，再调用 Windows 提醒/声音；不把“发送成功”写成“用户已看到”。

崩溃窗口按“账本权威、通知允许漏发”的边界处理：发送前崩溃可留下待尝试；发送后崩溃重启时由唯一键避免重复业务信号和重复尝试。状态查询不依赖进程内内存。

## 最小界面

实时提醒区域显示实例卡片/列表和软件内信号查询列表：实例、合约、中文周期、策略、状态、最近完成 K 线、最近计算、最近信号，以及信号的类别、方向、来源阶段和各通知渠道状态。常用按钮限定为启动提醒、暂停/恢复通知、静音/开启声音、停止实例、测试通知；账号和技术诊断保留在连接/高级区域。当前实时桥接入口一次只运行一个会话。

## 自动验收

- 同一完成 K 线重复输入：1 条业务信号、1 次通知尝试。
- 重新创建协调器/重启后重复输入：仍不重复。
- 恢复期信号：可查账本但不触发桌面/声音。
- 暂停只阻止通知尝试，静音只阻止声音，停止实例才停止计算。
- 最多 5 个活跃实例记录；Stopped/Failed 不占用名额，第 6 个活跃实例被拒绝。当前 UI 仍只有一个实时桥接会话入口。
- 同一实例/类别/方向可配置冷却秒数，默认 0；冷却只抑制通知尝试，不删除软件内信号，反向方向不受抑制。
- 测试通知不写入真实信号账本。

真实 TqSdk 账号、真实行情、断线现场、Windows 弹窗实际可见性和两个完整交易日列为人工/真实权限待验证。

## 实施结果

- 已新增 `live-notify.sqlite` 三表：`live_instances`、`live_signals`、`live_notification_attempts`；业务键和通知渠道均有 SQLite 唯一约束。
- 已接入 `LiveReminderEngine`：信号与通知状态先落盘，再 claim 为 `in_flight` 后调用 sink；重启会把未完成的 in-flight 标为失败并说明可能漏发，不自动重复桌面通知。
- 已在连接页增加 G5-A 实例列表、中文周期、软件内信号查询列表、冷却秒数、启动/暂停/静音/停止/测试通知等入口；测试通知不访问真实信号账本。
- `g5a-fixture-check` 通过：重复去重、重启去重、恢复期抑制、暂停/静音区别、崩溃窗口恢复、停止/失败拒绝、活跃实例上限、同向冷却/反向放行和状态持久化均为 true；退出码 0。
- 首轮发布包复核发现包内 Qh.Core/Qh.Cli 为旧二进制，包内 `g5a-fixture-check` 曾返回 usage/exit=2；本轮已全量同步当前 Release 输出并重新跑包内 G5-A/G4 fixture，均退出码 0，另核对源码/包内核心二进制哈希一致。
- 首轮审核时 `RunTqLiveAsync` 曾向引擎传入空候选；G5-B 已补上独立实时策略 Worker 和完成线求值，但仅完成合成端到端验证，未宣称真实 TqSdk 持续权限、断线现场或正式 G5。
