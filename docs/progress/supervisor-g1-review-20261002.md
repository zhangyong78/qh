## 必修问题

1. **SMA 读取未来数据。** Indicators.Calculate 使用 Skip 后对剩余全部行求均值，缺少窗口长度限定。输入收盘 10/11/12/11/10/9、N=3 时，第 3 根实际 10.5，预期 11；第 4 根实际 10.6，预期 11.333333；第 5 根实际 10.5，预期 11。同一第 3 根在三根前缀中为 11、完整序列中为 10.5，违反历史与实时一致性。应按已到达窗口增量计算，并验证前缀不变性。
2. **不同合约可混为一条序列。** 混合 rb2601 09:00 与 au2601 09:01 被成功发布为标识 rb2601 的快照，两行混合。第一版单合约导入必须明确拒绝不一致的合约、交易所、周期，不能取第一行标识而继续使用其它标识。
3. **中断发布重试会报假成功。** 负责人在独立测试目录构造只有 bars.csv 的中断状态；再导入返回 published=True，仍无 bars.parquet，查询抛 FileNotFoundException。发布必须在独立临时目录完整校验后提交；对既有目录检查完整性及摘要，不能仅检查 CSV 存在就跳过。取消、失败、中断后恢复都必须可验证。
4. **缺口算法误报和漏报。** 1 分钟 09:00→09:30 未报告缺口；5 分钟 10:10→10:30 将正常休市误报为缺口。现有“小于10周期”的阈值不能当交易时段规则。第一版可采用显式、版本化的测试交易时段表和导入配置，不必接联网日历，但要检测任意长度的时段内缺口，区分休市和未知规则。
5. **导入/查询与渲染仍会占用 UI 线程。** WPF 直接 await ImportAsync，读取后大量同步解析、排序、哈希和 DuckDB 操作继续在 UI 上下文执行；QuerySnapshot、指标和全部 Canvas 元素生成也在 UI 线程。另有每行 bars.Keys.Max 全表扫描。应把数据处理放后台、取消可及时到达，图表按可见窗口绘制，不把异步文件读取当全流程后台执行。
6. **图表交互缺失而不是只缺视觉验证。** 当前源码没有滚轮缩放、拖动平移、真实十字光标与价轴，只有 MouseMove 状态文字。应实现已要求的最小图表交互，并给出可复核的非人工证据；人工体验仍可如实标未验证。
7. **Worker 启动/退出需可靠。** Process.Start 的异常没有完整捕获；关闭时 UI 阻塞等待，而输出/退出事件同步 Dispatcher.Invoke 存在相互等待风险。应处理启动失败、异常退出、取消/停止超时和关闭确认，避免冻结或孤儿进程。
8. **G0 下穿样例数值错误。** 14/13/12/9 的第 3 根 SMA(2)=12.5、SMA(3)=13，已低于而非都为13，第4根不能称首次下穿。改用有正确前后关系的手算样例，例如 12/14/13/9，第3根快13.5慢13、第4根快11慢12，形成下穿。
9. **无偏移时间使用本机时区的风险。** DateTimeOffset.TryParse 通常可以解析无偏移时间，使后备的显式 +08:00 分支不执行。应区分有偏移和无偏移输入，保证无偏移一律按 Asia/Shanghai；不改变用户系统时区来测试。
