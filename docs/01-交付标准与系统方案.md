# 交付标准与系统方案

版本：v1.0  
日期：2026-10-02

## 1. 目标、范围与交付边界

最终用户能够完成：连接行情账号 → 下载历史 → 检查覆盖 → 浏览图表 → 加载 Python 策略 → 回放历史信号或模拟交易 → 查看结果 → 启动实时提醒。

第一版分为两个可独立交付的里程碑：

- A：离线研究版。历史导入、图表、Python 策略、信号回放、交易回测、结果导出。
- B：实时提醒版。在 A 上增加 TqSdk 实时订阅、完成 K 线后的策略执行、通知及断线恢复。

不纳入第一版：真实下单、账户资金查询、多账户、CTP 网关、期权、组合套利、麦语言兼容、云端运行、远程消息、多策略组合收益、参数优化平台、完整 IDE、任意 Python 代码的安全沙箱。

只有已完成的具体月份合约历史才能作为交易回测基础。主连允许浏览和信号研究；跨合约连续收益回测与自动换月不在第一版。到期的提醒实例暂停，由用户选择新合约并重新预热。

## 2. 技术方案与进程职责

| 层 | 初期选择 | 边界 |
|---|---|---|
| Windows 桌面 | C#、WPF、.NET 10 LTS、x64 | 页面、配置、任务状态、图表、通知 |
| Python 工作进程 | 一个随软件启动的管理进程；回测/用户策略使用受管理子进程 | TqSdk 接入、数据处理、指标、策略、回测 |
| 图表 | ScottPlot WPF，先做交互原型验证 | K 线、成交量、指标、信号；不修改策略状态 |
| 历史 | Parquet 分区文件，DuckDB 检索 | 按合约/周期/月发布；临时文件不可被正式查询 |
| 配置和结果索引 | SQLite | 配置、任务、数据清单、运行索引、提醒账本 |
| 本机通信 | Windows Named Pipes | 命令、进度、结果文件位置、行情增量、心跳 |
| 后期行情扩展 | 独立实时数据源接口 | 以后增加 CTP，不让策略感知 SDK 差异 |

界面与计算分进程，用户策略不能阻塞界面和 TqSdk 更新循环。策略工作进程收到标准化的完成 K 线；不直接持有行情账号或连接 SDK。进程异常由管理进程记录和显示，不能自动反复重启故障策略。

首个单合约策略可以单工作进程实现；通过并发验收后再支持本版上限。不提前引入消息服务器、微服务或服务端数据库。

界面关闭时明确确认是否停止实时提醒；本版无系统服务或后台托盘驻留。退出后停止策略、保存状态并结束受管理子进程。Windows 睡眠、重启期间本版不持续运行。

历史下载与实时订阅的账号会话管理集中在接入层，避免多个用户策略自行创建 TqApi 实例。并发/订阅限制在阶段 G0 用实际账号核实。

## 3. 数据获取、存储和口径

### 3.1 来源与权限

TqSdk 的普通 K 线序列接口最多提供每个序列最近 8000 根；DataDownloader 批量历史下载是专业版功能。第一版不能通过反复调用普通序列接口假装完成多年下载。

账号权限不足时明确显示可用范围，并允许导入规定格式的 CSV；不能把空数据当下载成功。CSV 导入不代替对原始数据使用授权的确认。

第一批真实验证使用用户选定的 3～5 个品种及具体合约。软件订阅上限暂定 20 个具体合约，首轮验收先用 5 个；超过上限需修改基准并重新测量。

### 3.2 数据模型

每条 K 线至少包含：内部合约标识、原始合约代码、交易所、周期、起止时间、交易日、开高低收、区间成交量、持仓量、完成状态、来源和数据版本。

同时保存合约乘数、最小变动价位、交易时段、有效期、元数据来源及有效日期。不能把当前合约元数据无说明地套用于所有历史时段。

所有显示时间使用 Asia/Shanghai。自然日期与交易日分开保存，夜盘、周末、节假日由交易日历和品种时段表决定，禁止用简单“日期加一天”推断交易日。

1 分钟线按交易时段聚合为 5/15/30/60 分钟。不可跨休市段拼成一根。日线优先使用供应商日线，明确收盘价和结算价区别；自聚合日线作为单独口径，不覆盖原始日线。

### 3.3 下载发布与质量检查

下载步骤：权限检查 → 合约/时间分段 → 临时文件 → 校验 → 标准化 → 发布新版本 → 更新覆盖清单。失败、取消或校验不通过均不发布不完整分区。

同合约、同周期、同来源的重叠 K 线按唯一时间边界幂等处理；内容冲突保留旧数据版本并生成冲突报告。不同来源不无声混合覆盖。未来 Tick 接入不能仅凭时间戳去重，因为同时间戳可有多次更新。

质量报告列出：申请区间、实际覆盖、行数、重复、冲突、时间乱序、异常 OHLC、非法价位、无效值、空成交量和疑似缺口。

休市不是缺口；无成交与丢失数据不能仅凭没有 K 线判定。检查结合时段、供应商生成规则和元数据；不确定时标记“疑似缺口”。不得自动造价填充缺失 K 线。

严格回测默认遇到所需字段错误或未处理缺口时不启动。用户可以显式改为探索模式，结果必须带“数据不完整”标记和具体问题，不能与严格结果混淆。

数据清单至少保存文件版本、覆盖范围、校验摘要和更新时间。回测锁定数据快照；下载新版本不能改变正在运行或已完成回测的输入。

## 4. 策略文件和统一执行规则

第一版加载本地可信 Python 文件，显示策略名称、版本、文件摘要、参数及参数约束。软件提供加载校验和错误定位，用户在外部编辑器中编写策略。本文件不包含策略代码。

策略只通过标准上下文读取已到达的历史序列、指标及模拟持仓，并输出信号或模拟交易意图。统一支持生命周期：加载、参数校验、初始化/预热、完成 K 线、停止、错误。

策略可以分两类：

- 信号策略：输出名称、方向/类别、说明、时间及参考价格。
- 交易策略：除信号外，定义单合约开平仓意图，用于模拟收益计算。

信号策略可以独立使用，不能因为没有交易指令而被拒绝加载。交易策略的提醒与模拟执行分开记录，信号不等于成交。

默认按已完成 K 线执行一次。预热数据只计算状态，不输出正式统计和通知。需要 N 根数据的指标在 N 根之前处于未就绪状态，不自动补零。开始日期之前可取预热数据，但结果统计从正式区间开始。

历史与实时使用同一份策略、参数、指标实现和完成 K 线规则。正式运行期间修改文件或参数，不影响当前实例；重载需停止实例、创建新版本并重新预热。

回测上下文不给策略暴露未来数据。由于 Python 文件是可信本地程序，仍可能自行访问文件、网络或未来数据；本版不宣称能够审计或阻止任意用户代码的作弊行为。

策略异常包括语法错误、参数错误、运行异常、超时和进程退出。必须记录策略版本、任务、K 线时间和错误位置。超时策略停止，不阻塞其他策略。

首批指标限定为 SMA、EMA、ATR；首批示例为均线交叉信号策略和相同信号下的单合约交易策略。MACD、RSI 等不作为首版必交项。

本版指标口径固定如下，G0 只需落实成接口说明和手算夹具，不再次让用户决定公式：SMA 是最近 N 根完成 K 线收盘价的算术平均；EMA 在第 N 根以这 N 根收盘价均值初始化，之后使用权重 2/(N+1) 递推；ATR 使用 Wilder 平滑，首根 TR 为高低差，其后 TR 为高低差、最高价与前收盘价之差绝对值、最低价与前收盘价之差绝对值中的最大值，初始 ATR 为 N 根 TR 的均值，其后 ATR 为“前 ATR × (N-1) 加本根 TR，再除 N”。均线交叉要求上一根快线不高于慢线、本根快线高于慢线；下穿方向相反。输入不足时未就绪，不补零；跨交易日连续计算，只有新实例或显式重新预热才重新初始化。

实时完成 K 线由接入层按供应商序列、完成状态及交易时段共同判定。通常新 K 线出现后确认上一根；时段最后一根需有明确关闭和同步规则。不能仅凭电脑时钟到点就把尚未同步的数据标为完成。重复确认不得重复执行策略；来源无法确认完成时显示等待状态。

## 5. 历史研究的两种模式

### 5.1 信号回放

显示信号总数、按类别统计、时间/价格/说明表，以及 K 线标记。可选择固定观察窗口，查看信号后价格变化；该统计是事件观察，不作为交易收益。

本版必交的是信号列表与图表联动。固定窗口统计属于后续可选项，不作为首轮交付必需条件。

### 5.2 模拟交易回测

只支持单个具体期货合约；初始持仓为零，不允许多空同时持有。支持开多、平多、开空、平空，反向意图先平后开，分别计算费用。

用户设置初始资金、单次手数、合约乘数、保证金率、开仓/平仓/平今费率和滑点。手续费按每手固定金额或成交金额比例二选一，配置版本保存在结果中。历史费率缺失时允许用户假设值，但报告须注明。

第一版仅模拟“完成 K 线产生意图，下一根有效 K 线开盘尝试成交”。滑点按不利方向的整数最小价位计算。不得按产生信号的同根收盘价成交。

订单在下一根有效 K 线仅尝试一次。资金不足、超出可接受价位、缺少必须数据或能够确认的封板不可成交时，记为未成交并写明原因；不自动追价。OHLC 无法确定实际可成交数量或盘口排队，因此报告显示“基于 K 线的近似撮合”。

止盈止损第一版按完成 K 线判断、下一根开盘执行。盘中触价止盈止损、同根先后顺序和限价排队不在第一版，不能在结果中隐含这些能力。

交易日内开平和跨交易日持仓分别计算平今/普通平仓费用，交易日映射必须正确。保证金不足禁止新增开仓；保证金超限作为风险事件记录，本版不模拟期货公司的实际强平机制。

持仓权益按收盘价盯市展示。第一版不重现逐日结算资金划转和历史动态保证金调整，报告注明假设。结束时保留未平仓及浮盈亏，不默默强制平仓。

必交结果：权益/净值曲线、总收益率、最大回撤、已平交易胜率、已平交易数量、总手续费、持仓明细、未成交意图、信号列表。零交易时相关比率显示“不适用”；不输出 NaN 或虚假 0% 胜率。

每份结果保存：策略文件快照及摘要、参数、合约元数据、数据快照、撮合/指标版本、时间区间、资金费用设置和软件版本。随机策略保存种子；使用外部网络或不可重复逻辑的策略明确标记不可保证复现。

## 6. 实时提醒规则

一个运行实例由策略版本、参数、合约、周期和提醒配置组成。本版目标上限为 5 个同时运行实例，用户策略执行耗时必须受限。

实例状态：已停止 → 预热 → 运行；异常分为等待数据、断线暂停、策略故障、合约到期。恢复后检查缺口并预热，再切换到运行。不同状态在页面明确显示。

去重键包括实例、策略版本、合约、周期、K 线结束时间、信号类别及方向。账本持久化，重启后不重复推送已处理信号。冷却时间默认 0，按同实例同类同方向控制；反方向不被无意屏蔽。

软件内信号记录是权威结果。通知分为：已记录、待通知、已尝试通知、被冷却抑制、恢复期历史信号。系统通知是否实际被用户看见无法保证，状态不得写成“用户已收到”。

先持久化信号和通知尝试状态，再调用 Windows 通知，以优先避免重复。崩溃窗口可能造成桌面通知未出现，但信号仍应能从列表查看；不得承诺系统通知绝对恰好一次。

新运行与旧运行使用独立信号记录。已有结果页只读取已保存的信号，不因查看、筛选或缩放而重新执行策略。必要时创建新研究运行以使用新数据或新策略。

启动、预热及断线补缺产生的历史信号可以在记录中查看，默认不弹窗或播声音。恢复后只提醒已进入正常运行状态的新完成 K 线，避免集中补发。补缺未完成不能显示“正常运行”。

声音/桌面通知均可分别开关。静音只关闭声音；暂停通知不暂停计算和软件内信号记录；停止实例才停止该实例的策略计算。到期前提醒后，通知设置可自动恢复。

不同实例同时触发时，软件内逐条记录，系统通知允许在短时间窗聚合显示。通知被 Windows 禁用时，软件显示配置状态并允许发起人工测试，不把人工测试计入真实信号。

软件、计算进程及行情连接必须正常运行才会产生实时提醒。电脑睡眠、软件退出、网络断开状态明确展示和记录。

## 7. 页面与后台任务标准

页面：总览、数据中心、行情图表、策略管理、历史研究、实时提醒、运行日志、设置。

所有长任务均展示阶段、进度（只有总量已知才显示百分比）、耗时和取消入口。不编造 ETA。取消先显示“正在取消”，收到工作进程确认后才显示“已取消”。

下载取消保留已发布完整分区；未完成临时数据可续传但不可查询。回测取消不发布完整成功报告，可查看日志及明确标识的部分结果。删除操作说明数据范围和引用关系，不删除正被回测或运行实例使用的数据。

界面错误显示用户能采取的下一步和可展开技术详情。日志中的密码、令牌和账号敏感字段必须脱敏。策略输出限流并分段存储，防止无限打印耗尽磁盘或卡住界面。

## 8. 性能与稳定性验收

基准机器在 G0 登记 CPU、内存、SSD、Windows、运行时版本和显示缩放。默认目标为 Windows 11 x64、16GB 内存、NVMe SSD；所有数值都是待实测的交付目标。

| 编号 | 测量内容 | 基准/目标 |
|---|---|---|
| P01 | 冷启动到可操作首页 | 5 次记录，目标 5 秒以内；账号网络握手另计 |
| P02 | 本地 1 万根 K 线首次显示 | 5 次记录，目标 1 秒以内；注明缓存状态 |
| P03 | 下载/回测期间窗口交互 | 可切页、缩放、取消，无持续超过 1 秒的无响应 |
| P04 | 简单策略离线回测 | 固定 100 万根合法 K 线、固定版本，目标 30 秒以内，不含首次导入 |
| P05 | 完成 K 线到通知尝试 | 5 合约/5 轻量实例，正常状态 P95 低于 1 秒；不含供应商传输及 Windows 展示延迟 |
| P06 | 取消回测 | 正常任务 2 秒内响应；失联工作进程 5 秒内可结束并清理状态 |
| P07 | 连续运行 | 至少 2 个完整交易日，包含夜盘、断网恢复；无重复有效信号或持续积压 |
| P08 | 资源使用 | 空闲目标低于 1GB，总体研究负载目标低于 4GB；记录热身后的内存趋势 |

P04 使用明确标记的合成性能数据，不能冒充真实行情。真实数据至少验证 3 个不同交易时段品种。性能日志记录阶段时间、策略时间、队列长度和资源峰值；目标未达到时提供测量和最小调整建议，不盲目改架构。
