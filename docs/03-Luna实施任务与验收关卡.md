# Luna 实施任务与验收关卡

版本：v1.0  
日期：2026-10-02  
适用范围：Windows 11、本地个人研究软件、首版离线研究与本机提醒

## 0. 使用方式与当前状态

本文件把 [交付标准与系统方案](01-交付标准与系统方案.md) 和 [交互流程与页面状态](02-交互流程与页面状态.md) 拆成可以逐关审核的任务。每一关都必须先完成本关交付物，再由根代理按验收编号审核；未通过不得报本关完成，也不得进入下一关。

当前用户明确要求“本轮不写代码”，编码范围仍在澄清。因此当前状态固定为 **G0 设计/环境事实记录阶段，尚未开始编码**。本文的任务单用于用户后续明确开始开发后的执行，不代表任何程序、依赖、账号连接或系统功能已经完成。

本轮已完成的动作仅包括读取方案文档和只读环境检查：没有修改 00/01/02 文档，没有安装依赖，没有联网登录，没有使用真实账号。

### 0.1 不可自行扩大的范围

- 首个开发任务必须是“本地 CSV → 校验/发布 → K 线图表”，不需要账号、TqSdk 或网络。
- Python 策略只按可信本地文件处理，不承诺安全沙箱，不额外设计权限隔离产品。
- 首批指标只包含 SMA、EMA、ATR；首批示例固定为均线交叉信号策略，以及使用同一信号的单合约交易策略。MACD、RSI 等不作为首版必交项。
- 已完成 K 线产生意图，第一版只在下一根有效 K 线开盘尝试成交。
- 止盈止损第一版只按完成 K 线判断，再按下一根有效 K 线开盘规则处理；不实现盘中双触发先后判断，不实现限价排队。
- 原始信号回放结果查看时不重算、不覆盖原始信号；历史研究执行如果需要重新计算，必须创建新的运行记录。
- Windows 通知先持久化信号和通知尝试状态，再调用系统通知。采用少重复策略，但不承诺系统通知恰好一次；崩溃可能造成桌面通知漏发，信号账本仍须保留；“发送成功”不等于“用户已看到”。
- 断线恢复期间产生的历史信号只记录，不弹窗、不播声音；不增加自动补发摘要、复杂静默过滤或远程通知。
- 本版不开发真实下单、CTP 网关、账号资金查询、多账户、组合回测、参数优化平台、完整 Python IDE 或云端服务。

## 1. 约束与角色

### 1.1 约束

1. 只修改当前关卡需要的文件和代码；发现无关问题先记录，不顺手重构。
2. 所有实现和命令以 Windows 11 + PowerShell 7 为默认环境，不默认使用 Bash 命令。
3. 优先完成可离线、可复现的本地链路，再接入账号和网络数据。
4. 回测输入必须绑定数据快照、策略版本、参数、撮合规则和软件版本。
5. 实施任务应先形成最小可验证闭环，不能把所有单元测试、性能测试和外部网络测试提前堆到 G0；每关只准备本关必要的固定夹具和验收证据。
6. 不把合成数据、模拟账号权限或开发机运行结果描述成真实账号、无开发工具安装或长时间运行已通过。
7. 任务取消、进程退出、断网和权限不足都是正常验收路径，不得只验收成功路径。

### 1.2 角色和责任

| 角色 | 责任 | 不能替代的决定 |
|---|---|---|
| 用户/需求方 | 冻结范围，提供可用的 CSV、目标品种和后续 TqSdk 账号，确认业务口径 | 不由代理猜测账号权限、费率和未说明的交易规则 |
| 根代理 | 分配任务，审核每关证据、范围变更和失败原因，决定是否放行下一关 | 未通过不得把关卡标记为完成 |
| Luna 执行代理 | 按本文件实施当前关卡，维护任务记录，运行适当验证并报告事实 | 当前不写代码、不安装依赖；进入开发后可按任务安装必要的隔离依赖，不盲目升级全局环境或扩大功能范围 |
| 数据源/账号 | 提供实际行情、历史覆盖和权限能力 | 供应商能力不能由本地程序假设替代 |

### 1.3 关卡状态

每关使用以下状态：`未开始`、`进行中`、`待根代理审核`、`通过`、`阻断`。只有根代理确认的 `通过` 才能进入下一关。阻断时保留已完成的可复用产物、证据和下一步所需决定，不把失败结果包装成部分完成。

## 3. G0：环境与语义冻结

预计工作量：0.5～1.5 个工作日（只读检查、设计确认和夹具说明；不含安装依赖和编码）。

### 3.1 按序任务

1. **记录环境事实。** 用 PowerShell 记录 Windows 版本、PowerShell 版本、CPU/内存/磁盘、显示缩放、`dotnet --info`、`dotnet --list-sdks` 和 `python --version`。记录 PATH 中实际命令路径，不能只写“已安装”。
2. **对照目标运行时。** 01 文档的目标是 .NET 10 LTS；若当前环境只存在运行时而没有 SDK，登记为开发前需要解决的环境缺口。本轮不安装；进入开发后，由根代理安排必要 SDK 和项目/用户目录中的隔离依赖，不把常规依赖准备变成额外用户确认步骤，不升级已有全局 Python 环境。
3. **冻结时间语义。** 写明 Asia/Shanghai、自然日期与交易日、夜盘跨午夜归属、交易日历、休市段和未完成 K 线规则。准备跨午夜、周末/节假日前后夹具的预期。
4. **冻结信号与回测边界。** 写明完成 K 线信号、历史信号回放、历史研究新运行、交易意图、下一根开盘尝试、止盈止损完成 K 线判断和“不实现盘中双触发/限价排队”。已有结果页只读已保存信号；重新计算必须创建新运行。
5. **冻结指标和实时完成条件。** 写明 SMA、EMA、ATR 的公式、EMA 初值、ATR 平滑方式和预热要求；实时完成 K 线必须由接入层根据供应商序列、完成状态及交易时段确认，不能只按墙上时钟到点假定完成。
6. **冻结通知与恢复边界。** 写明信号账本是权威记录、通知尝试状态先落盘、桌面通知不保证恰好一次、断线补缺只记录不弹窗。
7. **整理最小固定夹具。** 每个夹具写明输入、顺序、手算预期和对应验收编号。只准备本关必需的夹具，不在 G0 生成完整单元测试套件。
8. **确认数据与账号边界。** 记录首批目标品种尚待用户选择、CSV 最低字段、TqSdk 权限待实际账号验证、历史数据授权和本地保存规则。

### 3.2 交付物

- 环境事实记录，包含本次检查结果：Python `3.12.10`，可找到 `C:\Users\31612\AppData\Local\Programs\Python\Python312\python.exe`；可找到 `C:\Program Files\dotnet\dotnet.exe`，Host `8.0.7`，Windows Desktop Runtime `8.0.7`，`dotnet --list-sdks` 显示没有已安装 SDK；本次没有安装任何 SDK 或依赖。
- 语义冻结表和待用户确认项。
- CSV、跨午夜、缺口、同 K 线信号、成交和通知恢复的最小夹具说明。
- G0 验收记录、阻断项和是否允许开始 G1 的结论。

### 3.3 G0 验收与阻断条件

- 通过 `G0-ENV-01～04`：环境事实可复核；开发所需 SDK/运行时策略明确；当前不写代码的约束写入任务状态。
- 通过 `G0-SEM-01～06`：A04、A07、A08、A09、A13、A14 的关键口径没有互相矛盾；01 和 02 的页面行为与语义一致。

### 3.4 固定验收夹具

**夹具 F01：首个固定回测样例。** 虚构合约乘数 10、最小价位 1、初始资金 10000、1 手、保证金率 10%、开仓费每手 2、平今费每手 3、普通平仓费每手 1、单边滑点 1 个价位。三根 K 线开盘分别为 100、102、106；第一根完成后产生开多意图，第二根完成后产生平多意图。按下一根有效 K 线开盘尝试并计入不利滑点，买入 103、卖出 105，毛利润 20、手续费 5、净利润 15、期末权益 10015、收益率 0.15%、持仓为零。界面必须分别显示信号 K 线和成交 K 线。此样例只验证计算，不代表真实费率。

**夹具 F02：信号与成交分离。** 一根完成 K 线产生信号但下一根因资金不足或缺少数据未成交；预期信号数量增加，成交数量为零，回放结果不产生收益字段，回测结果显示未成交原因。

**夹具 F03：时间与缺口。** 23:00 和次日 01:00 属于同一交易日；休市段不聚合成连续 K 线；有效时段内缺少一段 K 线时严格回测阻止启动，探索模式必须携带“不完整”标记。

**夹具 F04：通知恢复。** 同一实例、策略版本、合约、周期、K 线结束时间、信号类别和方向重复输入；账本只保留一个业务事件。断线补缺产生的信号只进入记录，不产生桌面通知。崩溃窗口只要求状态可追踪和少重复策略，不承诺系统通知一定出现或恰好一次。

**夹具 F05：指标和完成状态。** 用均线交叉信号策略分别验证 SMA、EMA、ATR 的预热不足、正式区间开始和首个交叉信号；策略只能在接入层确认 K 线完成后执行。重复确认同一根 K 线不得重复执行；仅因墙上时钟到点但供应商完成状态未知时，实例必须保持等待。

空头、反向、资金不足、零交易、跨交易日普通平仓、比例费用、跳空和期末未平仓样例在 G0 列出手算预期；不能用 F01 一个盈利样例代替 A09 的全部规则验证。

### 3.5 下一关入口

只有用户明确“开始编码”、G0 语义无阻断、根代理审核环境和夹具记录后，才允许进入 G1。若用户尚未明确，状态停留在 G0，不提交“已开始开发”的报告。

## 4. G1：本地数据、图表与进程骨架

预计工作量：2～4 个工作日（首个可视闭环；不接账号、不依赖 TqSdk）。

### 4.1 按序任务

1. 建立最小本地工作区和数据目录约定，明确源 CSV、临时文件、已发布数据、SQLite 索引和日志目录；不发布未校验临时文件。
2. 完成 CSV 字段映射、时间解析、时区/交易日字段、OHLC/成交量校验、重复和缺口报告。首轮只支持方案冻结的最低字段。
3. 将通过校验的 CSV 发布为本地可查询数据快照，记录来源、覆盖范围、版本和校验摘要；失败或取消不得发布不完整数据。
4. 用本地快照显示单合约 K 线、成交量、十字光标和时间标签；首批只实现或验证 SMA、EMA、ATR 的图表叠加，不提前增加指标体系。
5. 建立 WPF UI、协调进程、受管理 Worker 的最小心跳/退出协议；先验证启动、进度、错误和取消状态，不执行 Python 策略。
6. 用小型 CSV 完成“导入 → 图表 → 查看质量报告”按序走查，保留证据。

### 4.2 交付物

- 可重复导入的 CSV 夹具和本地数据快照。
- 数据质量报告、覆盖清单和目录说明。
- 最小 K 线图表页面及导入/查询交互。
- 进程骨架、运行日志、取消和退出清理记录。
- G1 验收报告，明确哪些是合成数据、哪些未测。

### 4.3 验收编号与阻断条件

- 关卡编号：`G1-DATA-01～05`。
- 产品编号：A01（离线入口）、A03（重复导入）、A04（时间/休市口径）、A05（图表）、A16（进程清理）的离线部分；必要时补充 P02/P03 的测量记录。

### 4.4 下一关入口

本地 CSV 到图表链路稳定、进程骨架能启动/取消/退出、根代理确认 A01/A03/A04/A05 离线部分后进入 G2。没有账号不是阻断条件，G1 设计上不依赖账号。

## 5. G2：Python 信号回放

预计工作量：2～4 个工作日（单策略、单合约、完成 K 线信号闭环）。

### 5.1 按序任务

1. 冻结本地可信 Python 策略的最小输入输出契约、版本摘要、参数和预热状态；首个示例使用均线交叉信号策略，不实现安全沙箱。
2. 在受管理 Worker 中加载策略，向策略提供已经到达的完成 K 线和预热数据；未完成 K 线不得成为正式信号输入。
3. 将信号写入不可变的信号运行结果，包含策略版本、参数、数据快照、K 线结束时间和信号唯一键。
4. 完成历史信号列表、图表联动、方向/类别/时间筛选和运行日志；无信号显示正常空结果。
5. 明确区分“查看已有原始回放结果”和“按新配置重新研究”。已有结果查看、筛选和图表缩放只读已保存信号；后者创建新的运行 ID，不覆盖原运行或重写原始信号。
6. 验证策略错误、超时、Worker 退出、取消和重复运行；只补本关需要的固定夹具，不提前写全部回测测试。

### 5.2 交付物

- 一个可信本地信号策略示例及版本快照。
- 信号运行记录、信号表、图表标记、日志和导出文件。
- 预热、不完整数据、策略异常、取消和重复运行证据。
- G2 验收报告。

### 5.3 验收编号与阻断条件

- 关卡编号：`G2-SIG-01～05`。
- 产品编号：A06、A07、A08、A11、A12 的信号部分，A05 的信号联动部分，以及 P03/P06 的适用部分。首个示例必须是均线交叉信号策略；SMA、EMA、ATR 的口径由 G0 固定并在结果中可追溯。

## 6. G3：模拟交易回测

预计工作量：3～6 个工作日（固定单合约、单持仓方向模型；不接真实行情）。

### 6.1 按序任务

1. 将交易策略意图与 G2 信号分开建模，建立订单、成交、持仓、费用和权益记录；信号仍不等于成交。
2. 实现唯一冻结的成交规则：完成 K 线产生意图，下一根有效 K 线开盘尝试一次，按不利方向整数最小价位计算滑点。
3. 实现资金、乘数、保证金、固定费用/比例费用、平今/普通平仓费用和零交易展示；保持单合约、初始空仓、不允许多空同时持有。
4. 实现止盈止损第一版口径：只用完成 K 线判断，按下一根开盘规则处理；不得添加盘中双触发、限价排队或盘口撮合。
5. 实现期末未平仓、浮盈亏、未成交意图、异常数据和取消结果的单独展示；不默默强平。
6. 按 F01 手算样例验证，再依次补 F02、空头、反向、资金不足、零交易、跨交易日普通平仓、比例费用、跳空和缺口样例。预期先由根代理审核，再与实现结果比对。
